This is a demonstration of a form that is vulnerable to Cross-Site Request Forgery (CSRF) attacks. Use this with CSRF-Blaster GUI to understand how CSRF vulnerabilities can be detected and exploited.

Why This Form Is Vulnerable

This form is vulnerable to CSRF attacks for several reasons:

  1. No CSRF Token: The form does not include a CSRF token, which would allow the server to verify that the request came from a legitimate page.
  2. Uses Standard Form Submission: The form uses a standard POST method that browsers will automatically include cookies with.
  3. No Origin Checking: The server does not validate the origin of the request.

How To Protect This Form

To protect this form against CSRF attacks, you should:

// Server-side implementation (Node.js/Express example) const express = require('express'); const csrf = require('csurf'); const cookieParser = require('cookie-parser'); const app = express(); // Setup middleware app.use(cookieParser()); app.use(express.urlencoded({ extended: false })); app.use(csrf({ cookie: true })); // Add CSRF token to all rendered templates app.use((req, res, next) => { res.locals.csrfToken = req.csrfToken(); next(); }); // In your HTML form, add the CSRF token: // <input type="hidden" name="_csrf" value="{{ csrfToken }}"> // Handle CSRF errors app.use((err, req, res, next) => { if (err.code === 'EBADCSRFTOKEN') { return res.status(403).send('CSRF validation failed'); } next(err); });
