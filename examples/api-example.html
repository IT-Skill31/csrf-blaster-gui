User Settings API

This example simulates a user settings API endpoint that allows users to update their preferences.

Endpoint

POST /api/user/settings

Why This API Is Vulnerable

This API endpoint is vulnerable to CSRF attacks for several reasons:

  1. No CSRF Token Validation: The server does not require any CSRF token in the requests.
  2. Reliance on Cookies: The API uses cookies for authentication (`credentials: 'include'`), which are automatically included in cross-site requests by browsers.
  3. No Origin/Referer Checking: The server does not validate the origin or referer header to ensure requests come from the same site.
  4. Processes State-Changing Operations: The endpoint modifies user data, making it a prime target for CSRF attacks.

Attack Scenario

An attacker could create a malicious website with the following code:

<!DOCTYPE html> <html> <head> <title>Cute Puppies</title> </head> <body> <h1>Look at these cute puppies!</h1> <img src="https://example.com/puppies.jpg" width="500"> <!-- Hidden CSRF Attack Code --> <script> // This will run when a victim views the page fetch('https://your-vulnerable-site.com/api/user/settings', { method: 'POST', headers: { 'Content-Type': 'application/json' }, credentials: 'include', // Includes the victim's cookies body: JSON.stringify({ theme: 'dark', notifications: 'none', language: 'fr' }) }); </script> </body> </html>

When a victim who is logged into your site visits this malicious page, their browser will automatically send their cookies with the request, allowing the attacker to change their settings without their knowledge or consent.

How To Protect This API

To protect this API endpoint against CSRF attacks, you should implement one or more of these measures:

1. CSRF Tokens

// Server-side implementation const express = require('express'); const csrf = require('csurf'); const cookieParser = require('cookie-parser'); const app = express(); // Middleware app.use(cookieParser()); app.use(csrf({ cookie: true })); // Provide CSRF token to client app.get('/api/csrf-token', (req, res) => { res.json({ csrfToken: req.csrfToken() }); }); // Protected API endpoint app.post('/api/user/settings', (req, res) => { // CSRF protection is automatically applied by the csurf middleware // It will throw an error if the token is missing or invalid // Process the request... }); // Client-side implementation async function getCSRFToken() { const response = await fetch('/api/csrf-token'); const data = await response.json(); return data.csrfToken; } async function updateSettings() { const csrfToken = await getCSRFToken(); fetch('/api/user/settings', { method: 'POST', headers: { 'Content-Type': 'application/json', 'CSRF-Token': csrfToken // Include the token in headers }, credentials: 'include', body: JSON.stringify(data) }); }

2. SameSite Cookies

// Set cookies with SameSite attribute app.use(cookieParser()); app.use(session({ secret: 'your-secret-key', resave: false, saveUninitialized: true, cookie: { secure: true, // For HTTPS sameSite: 'strict' // Prevents the cookie from being sent in cross-site requests } }));

3. Custom Request Headers

// Client-side: Add a custom header that can't be set by simple cross-site requests fetch('/api/user/settings', { method: 'POST', headers: { 'Content-Type': 'application/json', 'X-Requested-With': 'XMLHttpRequest' // Custom header }, credentials: 'include', body: JSON.stringify(data) }); // Server-side: Verify the custom header is present app.post('/api/user/settings', (req, res) => { if (req.headers['x-requested-with'] !== 'XMLHttpRequest') { return res.status(403).json({ error: 'CSRF protection' }); } // Process the request... });

Demonstration With CSRF-Blaster GUI

When testing this API with CSRF-Blaster GUI:

  1. Add this API endpoint to the "API Endpoints to Test" section
  2. Set the path to /api/user/settings
  3. Set the method to POST
  4. Set the data to {"theme":"dark","notifications":"all","language":"en"}
  5. Run the test

The CSRF-Blaster GUI will:

  1. Create a test payload that tries to make a cross-site request to this endpoint
  2. Test if the request succeeds without proper CSRF protection
  3. Report that the endpoint is vulnerable if the request is successful
  4. Provide recommendations for implementing proper CSRF protection
